# Refactoring Guide - Modular Structure\n\n## Overview\n\nThe codebase has been refactored from a monolithic `app.py` into a modular, maintainable structure following Flask best practices.\n\n## New Structure\n\n```\nproject/\n├── app.py                    # Main Flask app (40 lines, clean)\n├── config.py                 # Configuration & constants\n├── database.py               # Database initialization & schema\n├── models.py                 # Database access layer (queries)\n├── validators.py             # Input validation functions\n├── utils.py                  # Decorators, audit logging, security\n├── blueprints/\n│   ├── __init__.py\n│   ├── auth.py              # Authentication routes (login/logout/setup)\n│   ├── patients.py          # Patient management (CRUD, follow-ups)\n│   └── admin.py             # Admin-only routes (users, capacities)\n├── templates/\n│   └── index.html           # (still monolithic, can be split further)\n├── static/\n│   └── (CSS, JS)\n└── yanet_portal.db          # SQLite database\n```\n\n## File Descriptions\n\n### Core Application\n\n#### `app.py` (40 lines)\n- Minimal Flask app initialization\n- Blueprint registration\n- Database initialization\n- PyInstaller support for executable packaging\n\n#### `config.py`\n- All constants and configuration settings\n- Database path, valid units, validation patterns\n- Flask app config (SECRET_KEY, cookies, etc.)\n- Bed capacity defaults\n- Easy to maintain and modify settings globally\n\n#### `database.py`\n- Database initialization function (`init_db()`)\n- Schema creation for all tables\n- Centralized location for DB setup\n\n### Data Access Layer\n\n#### `models.py`\n- Database connection management\n- Query functions for CRUD operations:\n  - `get_patient()`, `update_patient()`, `get_all_patients()`\n  - `get_user()`, `get_user_by_username()`, `get_all_users()`\n  - `get_global_settings()`, `get_global_setting()`\n  - `count_occupied_beds()`, `get_room_transfers()`\n- Benefits:\n  - Single source of truth for queries\n  - Easy to debug SQL issues\n  - Testable in isolation\n  - Reduces code duplication in routes\n\n### Validation & Security\n\n#### `validators.py`\n- Input validation functions:\n  - `parse_date()` - Date format validation\n  - `valid_choice()` - Enum validation\n  - `required_text()` - Required string fields\n  - `validate_username()` - Username format\n  - `validate_password()` - Password requirements\n  - `validate_passwords_match()` - Password confirmation\n- Benefits:\n  - Reusable validation logic\n  - Consistent error messages\n  - Easy to modify validation rules\n\n#### `utils.py`\n- Decorators:\n  - `@login_required` - Check user is authenticated\n  - `@admin_required` - Check user is admin\n- Utility functions:\n  - `get_csrf_token()` - CSRF protection\n  - `audit_log()` - Log actions to database\n  - `patient_is_editable()` - Check patient record state\n- Benefits:\n  - Centralized security logic\n  - Reusable decorators\n  - Consistent audit logging\n\n### Route Blueprints\n\n#### `blueprints/auth.py`\n- Authentication routes:\n  - `/setup` - Initial admin account creation\n  - `/login` - User login\n  - `/logout` - User logout\n  - `/account/password` - Change own password\n- Middleware:\n  - `load_user_and_check_csrf()` - Load user before each request\n  - `apply_security_headers()` - Security headers for all responses\n  - `inject_template_globals()` - Make CSRF token available in templates\n- Benefits:\n  - All auth logic in one place\n  - Easy to modify login flow\n  - Security middleware centralized\n\n#### `blueprints/patients.py`\n- Patient management routes:\n  - `/dashboard` - Main dashboard with statistics\n  - `/patient/<chart_number>` - Patient profile view\n  - `/admit` - Admit new patient\n  - `/discharge` - Discharge patient\n  - `/change_room` - Transfer between units\n  - `/log_pipeline_call` - Record follow-up calls (2w/4w)\n  - `/leave_waiting_list` - Remove from waiting list\n  - `/update_biopsy_result` - Update biopsy status\n  - `/unlock_profile/<chart_number>` - Admin unlock\n  - `/export_excel` - Export patient data\n- Benefits:\n  - All patient logic together\n  - ~500 lines vs 1000+ in monolith\n  - Clear separation of concerns\n\n#### `blueprints/admin.py`\n- Admin-only routes:\n  - `/admin/users` - Manage staff accounts\n  - `/admin/users` (POST) - Create new staff\n  - `/admin/users/<id>/password` - Reset password\n  - `/admin/users/<id>/toggle-active` - Enable/disable\n  - `/admin/capacities` - Update bed capacities\n- Benefits:\n  - Admin logic isolated\n  - `@admin_required` decorator ensures access control\n  - Easy to audit admin actions\n\n## Migration Benefits\n\n### Before (Monolithic)\n- 1031 lines in single `app.py`\n- Mixed concerns: routes, validation, DB, utilities\n- Hard to test individual functions\n- Difficult to locate specific functionality\n- Validation logic scattered throughout\n\n### After (Modular)\n- `app.py`: 40 lines\n- `blueprints/auth.py`: ~150 lines\n- `blueprints/patients.py`: ~500 lines\n- `blueprints/admin.py`: ~150 lines\n- `models.py`: ~100 lines\n- `validators.py`: ~50 lines\n- `utils.py`: ~60 lines\n- `config.py`: ~50 lines\n- `database.py`: ~100 lines\n\n### Advantages\n1. **Testability**: Each module can be tested independently\n2. **Maintainability**: Changes are localized to specific modules\n3. **Reusability**: Validation, models, utilities used across blueprints\n4. **Scalability**: Easy to add new features/blueprints\n5. **Readability**: Shorter files, clear purpose\n6. **Debugging**: Easier to trace issues to specific module\n7. **Collaboration**: Team can work on different blueprints simultaneously\n\n## Next Steps for Full Refactoring\n\n### 1. Split `index.html` into Separate Templates\n```\ntemplates/\n├── base.html                # Base layout with sidebar\n├── auth/\n│   ├── login.html\n│   └── setup.html\n├── dashboard.html           # Main dashboard\n├── patient/\n│   └── profile.html\n├── admin/\n│   └── users.html\n└── macros/\n    ├── forms.html          # Form components\n    └── modals.html         # Modal dialogs\n```\n\n### 2. Extract CSS and JavaScript\n```\nstatic/\n├── css/\n│   ├── base.css            # Base styles\n│   ├── dashboard.css\n│   ├── modals.css\n│   └── responsive.css\n└── js/\n    ├── app.js              # Main app logic\n    ├── modals.js           # Modal handlers\n    └── forms.js            # Form utilities\n```\n\n### 3. Create Service Layer (Optional)\n```\nservices/\n├── patient_service.py      # Patient business logic\n├── capacity_service.py     # Bed capacity calculations\n└── report_service.py       # Report generation\n```\n\n### 4. Add Tests\n```\ntests/\n├── test_validators.py\n├── test_models.py\n├── test_auth_routes.py\n├── test_patient_routes.py\n└── test_admin_routes.py\n```\n\n## How to Use the Refactored Code\n\n### Installation\n```bash\npip install flask flask-session werkzeug pandas openpyxl\n```\n\n### Running the App\n```bash\npython app.py\n```\n\n### Adding a New Blueprint\n1. Create `blueprints/newfeature.py`\n2. Define routes and import required modules\n3. Import and register in `app.py`:\n   ```python\n   from blueprints.newfeature import newfeature\n   app.register_blueprint(newfeature)\n   ```\n\n### Adding New Routes\n- For patient-related: Add to `blueprints/patients.py`\n- For auth: Add to `blueprints/auth.py`\n- For admin: Add to `blueprints/admin.py`\n- Use existing models and validators\n\n### Adding New Validation\n- Add function to `validators.py`\n- Import where needed\n- Use in route handlers\n\n## Configuration Changes\n\nAll configuration is in `config.py`. To modify:\n- Change bed capacity defaults: Update `BED_CAPACITY_DEFAULTS`\n- Add new valid units: Update `VALID_UNITS` and `CAPACITY_KEY_MAP`\n- Modify validation: Update regex patterns and constants\n- Flask settings: Update `FLASK_CONFIG`\n\n## Common Tasks\n\n### Debug a Route\n1. Find route in `blueprints/`\n2. Check validation in `validators.py`\n3. Check DB queries in `models.py`\n4. Add print statements or use Flask debugger\n\n### Fix a Validation Error\n1. Check `validators.py`\n2. Modify validation logic\n3. Update related routes if needed\n\n### Add Audit Logging\n```python\nfrom utils import audit_log\naudit_log(conn, 'action_name', chart_number, 'details')\n```\n\n### Add New Global Setting\n1. Add key to `BED_CAPACITY_DEFAULTS` in `config.py`\n2. Initialize in `database.py` `init_db()`\n3. Query with `get_global_setting(conn, 'key_name')`\n\n## Performance Considerations\n\n- Dashboard calculates metrics on every load - consider caching\n- Large Excel exports may be slow - consider pagination\n- Database queries are basic - add indexes if needed\n- CSRF token validation on every POST - acceptable overhead\n\n## Security Improvements Made\n\n- Centralized CSRF validation in auth middleware\n- Consistent password hashing\n- Audit logging for all important actions\n- Admin-only routes protected with decorator\n- Input validation on all user inputs\n- SQL injection protection via parameterized queries\n\n## Version Compatibility\n\n- Python: 3.7+\n- Flask: 2.0+\n- SQLite: Built-in\n- Pandas: 1.0+\n- Werkzeug: 2.0+\n\n## Troubleshooting\n\n### Import Errors\n- Ensure all modules are in the same directory as `app.py`\n- Check that blueprints are properly registered\n- Verify relative imports use correct paths\n\n### Database Errors\n- Check `DB_FILE` path in `config.py`\n- Ensure database has proper permissions\n- Run `init_db()` to recreate schema\n\n### Route Not Found\n- Check blueprint is registered in `app.py`\n- Verify route URL matches\n- Check decorators (@login_required, @admin_required)\n\n## Future Enhancements\n\n1.
